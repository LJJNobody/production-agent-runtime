# 指标复现方法

## 并发加速

比较对象必须是同一版本代码、相同任务数、相同模型后端和相同请求延时分布，只改变运行时
最大并发数。基线设为并发 1，候选设为并发 N。

```text
speedup = sequential wall time / concurrent wall time
```

报告任务成功数和墙钟时间。失败或取消任务不能从分母中静默删除。mock 延时实验只隔离调度
框架开销；真实供应商实验还需报告 P50/P95/P99、429 数量、token 数与服务端配额。

“10 个并发任务加速 9.9x”仅应在任务数 10、并发 10 的指定负载下表述，不能推导为任意
任务和任意并发都线性扩展。

## 可靠性

逻辑请求成功率定义为最终返回成功的逻辑请求数除以全部逻辑请求数。一次逻辑请求可能包含
多次底层 provider attempt，因此还必须报告：

- provider attempt 总数；
- retry 总数；
- 瞬时错误与永久错误数；
- circuit open 拒绝数；
- 总墙钟时间和并发数。

注入独立随机错误的 simulation 可以验证重试路径，但不能证明生产可用性。真实测量应至少
覆盖一个完整业务高峰窗口，并保留未加重试/限流/熔断的受控基线。高成功率如果以明显更高
尾延迟和调用成本换取，也应同时披露。

## 镜像大小

使用 `docker image inspect` 的 `.Size` 字节值，按十进制 MB 除以 1,000,000。记录
Dockerfile digest、基础镜像 digest、CPU 架构和构建时间。不同架构的 layer 大小不能直接
混为同一结果。
